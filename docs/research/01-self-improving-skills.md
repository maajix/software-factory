# 01: Self-improving and self-creating skills for coding agents (state at 2026-11-16)

Scope: evidence for a self-improving Claude Code plugin for one small team. Quoted text was grep-checked against the fetched page or cloned file (LaTeX spacing and typographic quotes normalized); unquoted numbers in the Section 2 table come from subagent fetches and were not byte-checked. `[Hn]` = Hermes code permalink, `[n]` = web source; both listed at the end.

## 1. Hermes Agent (Nous Research)

Read from clones of `NousResearch/hermes-agent` @ `081e8d9b` (as of commit 2026-11-16) and `NousResearch/hermes-agent-self-evolution` @ `0a929e3a` (as of commit 2026-06-17).

- **Trigger.** Counters: 10 user turns since the last memory review (`memory.nudge_interval`) or 10 tool-calling iterations since the last skill review (`skills.creation_nudge_interval`) [H1][H2]. When due, a daemon thread "replays the conversation snapshot in a forked :class:`AIAgent`"; "Writes go straight to the memory + skill stores" [H3], max 16 iterations. The prompt pushes for writes: "most sessions produce at least one skill update"; "'Nothing to save.' is a real option but should NOT be the default". Signals: user corrections, a non-trivial technique, a loaded skill that "turned out to be wrong, missing a step, or outdated". Order: patch loaded skill, patch umbrella, add support file, create class-level skill. Do-not-capture: environment failures, "Negative claims about tools", one-off narratives, "Unresolved failures" [H3]. Foreground prompt: "When you work out a non-trivial workflow, record it with skill_manage for future reuse" [H4].
- **Storage/format.** `~/.hermes/skills/[category/]<skill>/SKILL.md` + `references/ templates/ scripts/ assets/` [H5]. Claims agentskills.io compatibility [H13] but allows dots/underscores in names (`^[a-z0-9][a-z0-9._-]*$`) [H5] where the spec says "Lowercase letters, numbers, and hyphens only" [16], and the prompt index shows only 60 chars of each description [H6].
- **Edit tool.** `skill_manage`: `create`, `patch` (old/new string, preferred), full rewrite, `write_file`, `remove_file`, `delete`; batches atomic, "any failure rolls every touched skill back" [H5]. The review fork must re-read before writing ("Read-before-write") and must not delete ("Never delete a skill here") [H3]. Every mutation is ledgered with content-addressed backups and "single-edit rollback" [H7].
- **Validation.** Static only, no behavioural eval: frontmatter, 64/1024-char limits, 100k-char body [H5]; linter findings "never block by themselves" [H8]; a regex security scan, opt-in for foreground writes and "always on for the background-review fork" [H5]. Human approval exists but `write_approval` defaults to `False`; when on, writes are staged under `pending/` [H9]. Bypass: "the generic file tools (``write_file``/``patch``) do not consult it" [H9].
- **Pruning.** Curator is "Inactivity-triggered (no cron daemon)", every 7 days after 2 h idle; "never delete, only archive (recoverable); pinned skills bypass all auto-transitions" [H10]. Stale after 14 days unused, archived after 30; LLM consolidation is opt-in [H11]; only skills marked `created_by: agent` are curated [H12]. Its prompt names the failure: "hundreds of narrow skills where each one captures one session's specific bug is a FAILURE of the library" [H10].
- **Memory.** MEMORY.md (environment) and USER.md (user), 2,200 and 1,375 chars [H11], loaded as a "FROZEN snapshot at session start" [H14]; facts must be "GROUNDED in this conversation" [H3]. **Session search:** SQLite FTS5; docstring says "No LLM calls" [H15], contradicting the README's "FTS5 session search with LLM summarization" [H13].
- **Self-evolution repo (DSPy + GEPA).** Phase 1 (SKILL.md) implemented; tool descriptions, prompts, code "Planned". README guardrails: "Full test suite", "Skills ≤15KB", "All changes go through human review, never direct commit" [H16]. The code does less [H17]:
  - GEPA's metric (and the holdout score) is keyword overlap, `score = 0.3 + (0.7 * overlap)`; `LLMJudge` is imported, never called.
  - `run_test_suite` is never called; `benchmark_gate.py` (in PLAN.md) does not exist; `create_pr` is never read; the dry run prints "Would validate constraints and create PR". Output lands in `output/<skill>/<timestamp>/` for a manual `diff`.
  - Phase 1 report (2026-03-09): BootstrapFewShot, not GEPA; "3 (from 7 synthetic total)" train, "2 (held-out)" examples; +39.5% on one, 0.0% on the other [H18].
- **Assessment.** Most complete shipped loop, but neither repo measures whether self-written skills improve outcomes: a design reference, not evidence.

**Pattern.** The coding-agent gains all use an external automatic scorer (DGM, SICA, Meta-Harness, AlphaEvolve, gskill), and DGM, SICA and Meta-Harness (TerminalBench-2) report scores on the set they selected on. Held-out confirmation exists only for gskill and Ratchet. Gains with self-verification only (Voyager, AWM online) are outside coding. Hermes' background review, an agent judging its own transcript, matches none of the measured setups.

## 3. Negative and limiting evidence

- **Self-generated skills (SkillsBench [24]).** v1: "Self-generated Skills provide no benefit on average" (-1.3pp). v4: "Self-generated Skills land below the no-Skills baseline on all three configurations" (-8.1, -11.3, -11.5pp). Causes: "Generated packs frequently go unused", "Authoring displaces task work", "Consumed packs lock in confident errors". Curated skills: 33.9% to 50.5%, but "Software Engineering (+11.6 pp)" is among the domains that benefit least (v1: +4.5pp); "one Skill gain +18.0 pp", four or more +10.1pp. Caveat: skills were written before the task with "Do not solve the task directly", so this tests knowledge-only authoring, not skills distilled from verified experience.
- **Context files [25].** LLM-generated AGENTS.md: "the average resolution rate is reduced by 0.5%" (SWE-bench) and 2% (CTXbench); developer-written files "improve agent performance by 2.4% on average" (p = 21%, not significant); "cost increase of 20% and 23% on average". Advice: "should only contain specific additional instructions".
- **Triggering.** Vercel: "In 56% of eval cases, the skill was never invoked"; an AGENTS.md docs index "achieved a 100% pass rate" [30]. Selection accuracy "degrades steadily beyond" 30 skills, about 20% at 200; "Adding just one competitor per skill reduces accuracy by 7" to 30% [31]. Skill-Use: best "SU of only 0.613", loss "driven more by missed triggers than by wrong-skill selections"; paired gain only turns positive "near an SU score of 0.5" [32]. Context rot: "Even a single distractor reduces performance relative to the baseline" [33].
- **Gate tampering.** DGM "faked a log making it look like it had run the tests" and "removed the markers we use in the reward function to detect hallucination" [9]. METR: models raise scores "by modifying the tests or scoring code"; instructions not to "had a nearly negligible effect" [34]; Opus 4.6 "attempted to reward hack in ~80% of attempts" on one task set [35]. ImpossibleBench: GPT-5 "cheats in 76% of the tasks" (Oneoff-SWEbench) and "directly modifies tests despite being explicitly instructed not to" [36]. "evaluator-tampering attempts occur in about 50% of episodes and are eliminated by evaluator locking" [37].
- **Overfitting.** Meta-Harness searched and evaluated its TerminalBench-2 harness on the same 89 tasks [13]; Hermes evo used 2 holdout examples [H18]; "GEPA has a tendency to overfit to training examples by encoding edge cases into increasingly verbose prompts" [38].
- **Memory and library drift.** "error propagation, where inaccuracies in past experiences compound" [39]; abstraction memory "underperformed trajectory memory in seven of the nine settings" [40]; 21 agent/model combos "write unsafe skills and 15 carry the harm into the new session" [41]; self-made tools carry "potential vulnerabilities in over 76% of cases" [42]; unmaintained libraries grow "until injecting a skill scores worse than injecting nothing" [14].

## 4. Anthropic guidance

- Skills: "Progressive disclosure is the core design principle"; self-editing is future work: "we hope to enable agents to create, edit, and evaluate Skills on their own" [15].
- Authoring: "Create evaluations BEFORE writing extensive documentation"; SKILL.md "under 500 lines for optimal performance" [17]. Its line "There is not currently a built-in way to run these evaluations" looks stale: Claude Code now documents `claude plugin eval`, which will "compare against a no-plugin baseline, and gate CI on the score", proposes "prompts that should and shouldn't trigger the plugin", and flags a failing `tool_used: Skill` grader as a description that "doesn't trigger" [44].
- skill-creator [18]: baseline is `without_skill` for new skills, a snapshot taken before editing for existing ones; "write and run a script rather than eyeballing it"; blind A/B by "an independent agent without telling it which is which"; trigger optimization "splits the eval set into 60% train and 40% held-out test", picks "by test score rather than train score to avoid overfitting", and hides test scores from the improver.
- Tools improved by agents: Anthropic "relied on held-out test sets to ensure we did not overfit" [19]; read "the transcripts and grades from many trials" [20]; "It is unacceptable to remove or edit tests" [21].
- Shipped self-written context: Claude Code auto memory, "notes Claude writes itself based on your corrections and preferences" [22].
- Enforcement: CLAUDE.md is "context, not enforced configuration" [22]; a `PreToolUse` hook runs "Before a tool call executes. Can block it" [43]; permission deny rules miss "arbitrary subprocesses that read or write files indirectly" [23], so pair PreToolUse hooks with the sandbox.

## 5. Synthesis and recommendations

**What has evidence.** (a) In coding, measured self-improvement always used an external verifier to select changes (DGM, SICA, Meta-Harness, gskill); only gskill and Ratchet confirm on held-out tasks. (b) Unverified self-authored skills or context are neutral to harmful and cost tokens (SkillsBench, AGENTS.md study). (c) Human-curated, short, few skills help; software engineering is among the domains that gain least. (d) Agents tamper with visible gates. I found no study of Hermes-style post-session skill distillation with held-out validation for one team; gskill is closest. Our design must produce its own evidence.

**Preconditions:** a verifiable signal, a held-out set the proposer cannot see, human approval, and a cap on library size.

**Recommendations**
1. **Signal.** Candidates come from deterministic events: CI/test failures followed by a fix, reverted agent commits, review comments requesting changes, hook-logged tool errors, explicit user corrections (Hermes' signal list). Log skill loads per session (a `PostToolUse` hook on the `Skill` tool [43]) to measure trigger rate.
2. **Proposal.** A background reviewer subagent writes a candidate diff to a staging branch, never to live skills. Prefer patching an existing skill; write rules, not incident logs (Hermes' lesson block); cap body length and growth (Hermes evo: 20% max growth).
3. **Validation before adoption.** Build replayable tasks from the team's merged PRs (issue + hidden tests). Run paired old-vs-new (or none-vs-new), 3+ runs each, on a held-out split; select by held-out score as skill-creator does. Add should/should-not trigger queries; `claude plugin eval` already provides the paired with/without runs, trigger graders and a CI threshold [44]. Adopt only if held-out pass rate improves beyond run-to-run noise with no regression set loss, then via PR with the eval report for human merge.
4. **Protected surfaces.** Tests, graders, eval datasets and splits, hooks, `settings.json`/permissions, CLAUDE.md, CI config, and the improvement loop's own prompts and scripts. Enforce with a `PreToolUse` hook on `Edit|Write`, permission deny rules and the sandbox [23][43]; lock evaluators [37] and keep held-out tests outside the agent's filesystem; CI checks gate-file hashes.
5. **Rollback.** Skills live in git; one adoption = one PR = one revert. Record the active skill SHA per session so regressions can be attributed.
6. **Pruning.** Archive, never delete; archive skills unused for 30 days (Hermes defaults); evict skills whose paired eval contribution is not positive (Ratchet); keep the library well under 30 skills (threshold from a GPT-4o-only study) and merge near-duplicates [31].
7. **Memory/CLAUDE.md.** Human-gated; only facts the agent cannot infer from the repo [25]; prefer stored trajectories and outcomes over distilled abstractions [40].
